# N-002: Reconcile JaKooLit Preset with Hyprland 0.57 Lua Migration

- Status: Approved
- Priority: Unassigned
- Area: Phase 02 / Presets / JaKooLit / Hyprland compatibility
- Created: 2026-11-08

## Problem

The daily-use configuration is still deployed from the original `ZackMelza/hyprland` repository, using the generated `jakoolithyprl/active/` tree. Its `hyprland.conf` sources JaKooLit's split `.conf` configuration files. On 2026-11-08, the Arch Linux update upgraded Hyprland from `0.56.2-4` to `0.57.1-1`. Hyprland 0.57 removed support for the legacy Hyprland `.conf` configuration format and generated a default `hyprland.lua`; the personal desktop configuration stopped loading. This can happen without `hyprctl configerrors` reporting errors.

The existing `presets/jakoolit/` import in Linux-builds predates this compatibility change and is not yet live-verified. Its copied files and documentation will become stale as the original repository is migrated.

## Objective

Keep the original JaKooLit-based desktop functional on supported Hyprland releases while preserving personal customizations. After the original repository has a tested Lua-based configuration, update the imported JaKooLit preset in Linux-builds to reflect that tested source without accelerating the separate independent Hyprland/Quickshell development plan.

## Requirements

- Migrate the **original** `ZackMelza/hyprland` configuration to Hyprland 0.57-compatible Lua first. Preserve the shared, desktop, and laptop profile distinctions; keybinds; user settings; monitor/workspace overrides; autostart; animations; window/layer rules; theming; and scripts as appropriate.
- Keep the previous `.conf` sources and a rollback path until the new runtime is verified. Remember that hypridle, hyprlock, and other non-Hyprland config files may retain their own `.conf` formats.
- Update generated active-tree logic, entrypoint handling, guard/watchers, and health checks as necessary so a generated default `hyprland.lua` does not silently replace the managed configuration.
- Account for local uncommitted/generated state, `~/.config/hypr` symlinks, and runtime-only monitor, workspace, wallpaper, and Wallust data before changes.
- Check the original repository's changed files and Git history against `presets/jakoolit/`, preserving provenance and avoiding a blind overwrite of the imported preset.
- **Do not** deploy the Linux-builds JaKooLit preset onto the daily machine or claim the import is verified until a separate controlled migration/test is performed.
- Retain the independent Hyprland and Quickshell plans; do not substitute this preset compatibility fix for Phase 04/05 architecture work.

## Acceptance Criteria

- Original repo has a Lua entrypoint and all runtime-loaded Hyprland configuration paths work on a documented Hyprland 0.57.x environment.
- Live checks confirm display outputs and workspaces, default applications, launcher/Rofi, keyboard/media shortcuts, Waybar, notifications, startup, screen locking, wallpaper, and desktop/laptop-specific behavior where applicable.
- Autogenerated defaults cannot silently masquerade as a successful load of the personal config; health checks detect missing/incorrect entrypoints.
- Rollback and recovery instructions are documented and tested.
- Linux-builds `presets/jakoolit/` is reconciled with the **tested** original version, any path changes are handled explicitly, and static plus runtime verification results are documented.
- The migration is recorded in Phase 02 documentation and linked to its source commit/PR; the source repo remains available until the owner approves retirement.
